# Markdown Syntax: Part 1 - Exercise

Recreate the note shown in the reference image using Markdown. This exercise practices the five topics covered in [[3-markdown-syntax-pt1]]: headings, paragraphs and line breaks, text formatting, lists, and code.

## Instructions

1. Create a new vault named `3e`.
2. Inside the vault, create a note named `exercise-sol-3e` (the file will be `exercise-sol-3e.md`). Copy the text from the image and reproduce its structure and formatting using Markdown.
3. Add `# My First JavaScript Project` as Heading 1 in the Markdown source. Use Heading 2 for Project Notes, Technologies, and Setup, and Heading 3 for First Run.
4. Include the bold, italic, strikethrough, and highlighted text, along with the nested lists, inline code, and JavaScript code block.
5. Switch to Reading view and compare your note with the reference image.

Focus on the Markdown structure rather than exact font sizes, colors, or spacing, which depend on your theme. You can open the image to inspect it at a larger size.

Try writing the note yourself first. If you get stuck, refer to [[3-markdown-syntax-pt1]], then continue the exercise.

### Prompt

```text
Grade my Markdown exercise using the three attached files:
- exercise-sol-3e.md: my solution.
- 3e-markdown-syntax-reference.png: the reference image.
- 3e-markdown-syntax-exercise.md: the exercise instructions.

Compare my solution's Markdown source with the reference image and instructions. Give a score out of 100, with up to 20 points for each category:
1. Headings: correct text and levels for the H1 title (My First JavaScript Project), the H2 sections (Project Notes, Technologies, and Setup), and the H3 subsection (First Run). The H1 must appear in the Markdown source; the filename alone does not satisfy this requirement.
2. Paragraphs and line breaks: correct paragraph separation and line structure.
3. Text formatting: correct bold, italic, strikethrough, and highlighting.
4. Lists: correct ordered and unordered lists, indentation, and nesting.
5. Code: correct inline code, fenced code block, JavaScript language label, and code content.

Accept equivalent valid Markdown. Do not deduct points for theme-dependent font sizes, colors, or spacing. Where the image and instructions differ, follow the written instructions. Do not claim to have verified the vault name or editor settings from these files. If rendering depends on an Obsidian setting, state that limitation rather than assuming the setting.

Report each category's score and briefly explain any deductions. For each mistake, quote the relevant part of my solution, explain the issue, and show a minimal correction. Do not rewrite the entire note. Finish with the total score and the main things I should practice next. Give your feedback in Turkish.
```
